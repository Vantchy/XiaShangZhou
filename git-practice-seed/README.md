# Git 协作练习仓库

这是铸算·华夏纪项目组的练习仓库，用来在正式开工前把 GitHub 协作流程完整走一遍。这里随便改、随便错，不用有压力；只有两条当真：**不用 `--force`**，**不放任何真实密码和令牌**。

详细步骤看组里发的《操作清单与问题自查》；每项练习的完整说明在《试验仓库演练计划》里。本文件只列顺序和完成标志。

## 练习顺序

| 顺序 | 练习 | 完成标志 |
| --- | --- | --- |
| 0 | 准备：装 Git/VS Code、设置姓名邮箱、接受仓库邀请 | `git config --global --get user.name` 有正确输出 |
| 1 | 完整闭环：在 roster.md 加自己一行 → 分支 → 提交 → 推送 → PR → 被要求改一次 → 改完再推 → 审核通过 → 合并 → 回 main 同步 | main 的花名册里有自己一行 |
| 2 | Close 一个玩笑 PR | 说得清 Close ≠ 合并 |
| 3 | 无冲突同步：在别人合并后，用 fetch + merge 把最新 main 合进自己的分支 | 不重建分支就同步成功 |
| 4 | 冲突演练：两人改 game-rules.md 同一行同一个值的位置 → 一人先合并 → 另一人先 abort 一次、再正式解决 | 文件里只剩一个最终值，无冲突标记 |
| 5 | Push 被拒：同伴在网页端改你分支的文件 → 你本地提交后推送被拒 → fetch 看清原因 → 合进来再推 | 推送成功，且没用 --force |
| 6 | stash：改一半 playground.md → stash 收起 → pop 恢复 | 工作区能变干净、内容能回来 |
| 7 | .gitignore 实验：建 .env 和 node_modules，看 git status 是否理它们 | 能解释它们为什么不进仓库 |
| 8 | CI 红绿灯：往 playground.md 写一行 `<<<<<<< HEAD` 开 PR 看红灯，删掉再看绿灯 | 亲眼见过一次失败日志 |
| 9 | Issue 闭环：提一个 Issue → 同伴用 `Fixes #编号` 的 PR 合并后它自动关闭 | Issue 被自动关闭 |

## 文件说明

- `roster.md`：花名册，练习 1 的编辑对象
- `game-rules.md`：练习 4 的冲突现场，不要提前改里面的 MAX_PLAYERS
- `playground.md`：自由涂鸦区，练习 6、8 在这里做
- `.github/pull_request_template.md`：开 PR 时会自动带出的描述模板

卡住时的顺序：先查操作清单的「问题自查」→ 问搭档 → 群里问（带上当前分支名、git status 和报错原文）。
